> **현재 상태 (2026-10-16 실측)**
> - **데이터:**
>   - KOSPI·KOSDAQ: KRX 공식 일별 종가(2016-01-04부터) + 토스증권 당일 종가(잠정치, 다음 날 KRX 값으로 확정·대조)
>   - S&P 500·NASDAQ 100: 화면 표시는 FRED. 예측 학습에는 토스증권 SPY·QQQ ETF 가격을 씁니다.
>   - 거시지표: Fed H.15·H.10. 뉴스: Fed·SEC 공식 발표. 일정: FOMC.
> - **방향 예측:** 12개 조합(4개 시장 × 3기간) 중 **NASDAQ 100 1거래일**과 **KOSDAQ 5거래일**만 사전 고정 기준을 통과했고, 나머지는 NOT VALIDATED입니다.

## 1. 설치와 실행

필요한 것: Python 3.10+, `curl`, Node(테스트용, 선택), [uv](https://docs.astral.sh/uv/) 권장. DB 서버나 클라우드는 필요 없습니다. `make`가 없으면 각 타깃의 명령을 직접 실행하세요.

```sh
make setup                                     # = uv venv .venv && uv pip install -r requirements.txt
.venv/bin/python scripts/mi_cli.py all         # 수집 → 국면 → 학습 → 예측 → 뉴스 → 브리핑 (단계별 실패 격리)
make dev                                       # = python3 scripts/serve.py --port 3000 → http://localhost:3000
```

명령을 실행한 뒤에는 화면의 **JSON 다시 읽기**를 누르세요.

| 명령 (`.venv/bin/python scripts/mi_cli.py …`) | 하는 일 |
| --- | --- |
| `ingest` | 가격 수집(FRED·KRX), SQLite 보관, Fed 거시지표, 토스증권 당일 종가·SPY/QQQ |
| `regime` | 국면·위험·전일 대비 변화·최신 종가 오버레이 → `regime.json`, `macro.json`, `latest.json` |
| `train` | 라이선스 게이트 + walk-forward 검증 + 비용 반영 성과 → `performance.json` |
| `forecast` | 미판정 예측 판정 + 실시간 예측 추가 → `forecast.json` |
| `news` / `briefing` | 뉴스 메타데이터·분류 / 한국어 브리핑 |
| `status` | 시스템 상태, SQLite 무결성, 라이선스 표 |
| `morning` / `evening` / `weekly` / `all` | 위 단계를 묶은 복합 작업 |
| `backfill [--since YYYY-MM-DD]` | KRX 10년 이력 (재개 가능, 하루 8,000회 이내) |
| `backup` | `data/mi.sqlite` 온라인 백업 → `data/backups/` (자동 삭제 없음) |
| `label-export` / `label-score` | 뉴스 라벨링용 CSV / 정확도 채점 |

`MI_DATA_DIR=<폴더>`를 지정하면 모든 입출력이 그 폴더로 바뀝니다. 실데이터와 분리해 실험할 때 씁니다.

### API 키

키는 **저장소 밖 파일 하나**(`~/.config/mi/env`, 권한 600)에만 둡니다. `mi_cli.py`와 cron 래퍼가 자동으로 읽습니다. 파일이 본인 소유가 아니거나 권한이 600이 아니면 읽지 않습니다. 셸 코드로 실행하지 않고 아래 이름들만 읽습니다.

```sh
mkdir -p ~/.config/mi && chmod 700 ~/.config/mi
cat >> ~/.config/mi/env <<'EOF'   # 본인 터미널에서 직접 입력
export KRX_API_KEY=...            # KRX OPEN API (KOSPI/KOSDAQ 공식 종가)
export TOSS_CLIENT_ID=...         # 토스증권 Open API (당일 종가, SPY/QQQ) · WTS에서 발급 + 허용 IP 등록
export TOSS_CLIENT_SECRET=...
export ANTHROPIC_API_KEY=...      # 선택: AI 요약 (briefing --llm, 유료)
EOF
chmod 600 ~/.config/mi/env
```

- 표시 전용 참고 지표(`scripts/collect_macro.py`)는 `ECOS_API_KEY`(한국은행 ECOS)를 같은 터미널 환경변수로 받습니다.
- 확인: `python3 scripts/collect_data.py --check-krx 2026-10-14`

### 자동 실행

`scripts/schedule.example.cron` 참고. 시스템 시간대가 Asia/Seoul이어야 합니다(Debian 계열 cron은 `CRON_TZ`를 무시). 각 작업은 `scripts/cron_run.sh`로 실행되며, 이 래퍼가 키 파일을 읽고 `flock`으로 중복 실행을 막습니다.

| KST | 작업 | 의미 |
| --- | --- | --- |
| 08:30 (월–토) | `morning` | 미국 전일 종가(05:00/06:00 KST 마감) + KRX 공식값 확정. 개장 전 예측 |
| 16:30 (월–금) | `evening` | 토스 당일 종가로 한국 예측 (다음 거래일 개장 전이라 성과 집계 대상) |
| 일 10:00 | `weekly` | 재검증·재학습 |

- PC가 켜져 있어야 실행됩니다. 놓친 실행은 다시 돌지 않습니다.
- WSL은 터미널이 모두 닫히면 꺼질 수 있습니다. `data/cron.log`에 실행 기록이 있는지 확인하세요.

## 3. 방법론

### 시점 정합성 (미래 정보 누출 방지)
- 모든 관측값에 `available_at`(UTC), 모든 예측에 `decision_time`(장 마감 +30분)을 붙이고, `available_at ≤ decision_time`인 값만 as-of 조인합니다.
- 한국 예측은 전날 미국 종가까지만 봅니다(서머타임 포함 테스트).
- 공개 시점 가정:
  - H.15: 다음 연준 영업일 17:00 ET (연준 휴일 반영)
  - H.10: 주간 게시 (다음 주 화요일 16:15 ET)
  - KRX 교차시장 가격: 다음 평일 08:00 KST
  - 토스 일봉: 장 마감 15분 뒤 이전 봉(진행 중 세션)은 종가로 쓰지 않습니다.
- 결측 대체와 스케일링은 각 fold의 학습 구간 안에서만 적합합니다.

### 국면·위험·전일 대비 변화
- **국면:**
  - 추세 규칙 5개(종가 > 50·200일선, 50일선 > 200일선, 20·60일 모멘텀 > 0)로 −5..+5점을 매깁니다.
  - 20일 변동성의 1년 백분위가 0.70 이상이면 "높은 변동성"입니다.
  - 새 국면은 3일 연속 확인된 뒤에 바뀝니다.
  - 국면 이력은 각 날짜까지의 데이터로만 계산합니다.
- **위험 점수:** 실현변동성, 낙폭, VIX, 신용, 금리 변동, 원화를 균등 평균합니다. 쓸 수 없는 구성요소는 빼고 구성요소 수를 함께 표시합니다.
- **전일 대비 변화 (사전 고정, `daily-v1`):**
  - 국면 변경, 새 원시 신호, 위험 등급 경계 통과
  - 위험 점수 ±10점 이상(구성요소 집합이 같을 때만 비교)
  - 추세 점수 ±2 이상, 변동성 백분위 0.70선 통과
  - 미국 10년물 금리 ±10bp, USD/KRW ±1%
  - 일별 스냅샷은 감사 기록으로 추가만 하고, FRED 시장은 라벨만 저장합니다.

### 예측
- **라벨:** \(R_{t,h}=P_{t+h}/P_t-1\). \(|R| \le 0.43\,\sigma_{60}\sqrt{h}\)이면 Neutral, 그보다 크면 Bullish, 작으면 Bearish입니다. k=0.43은 사전 고정값입니다.
- **피처:**
  - 수익률, 이동평균 이격, RSI, MACD, 변동성, 낙폭
  - 미국 금리 수준·변화, 금리차, USD/KRW, 광의 달러지수
  - 다른 시장의 수익률, 모멘텀, 상관
  - **ML 권한이 있는 소스만** 씁니다. 제외된 피처는 `dropped_features`에 기록됩니다.
- **모델:** 과거 클래스 빈도, 모멘텀 규칙, 로지스틱 회귀, LightGBM. 보정은 none·temperature·sigmoid·isotonic 중에서 고릅니다.
- **검증:**
  - 시간순으로 개발(40%) → purge → holdout(60%)으로 나눕니다. holdout 시작일은 첫 실행 때 고정합니다.
  - 각 fold는 fit → purge → 보정 → purge → test 순서입니다.
  - 하이퍼파라미터와 주 모델은 개발 구간에서만 고릅니다.
- **통과 기준 (2026-10-15 사전 고정, 실행 중 변경 불가):**
  - 유효 표본 ≥ 50
  - 과거 클래스 빈도와 가장 강한 비교 모델 **모두**에 대해 log loss·Brier 개선의 블록 부트스트랩 90% 하한 > 0
  - 균형 정확도 +2%p 이상
  - 최악 클래스 ECE ≤ 0.08
  - 개발 → holdout log loss 악화 ≤ 10%
- **비용 반영 성과 (2026-10-16 사전 고정):**
  - 주 모델이 '상승'을 가장 높게 보면 h거래일 보유하고, 아니면 현금으로 둡니다.
  - 겹치지 않는 기간만 평가합니다.
  - 왕복 비용은 한국 0.10%, 미국 ETF 0.25%입니다.
  - 진입은 당일 종가와 하루 늦은 종가 두 가지로 계산합니다(시가 미보관).
  - 단순 보유 대비 초과수익의 90% 하한이 0보다 클 때만 "비용 차감 후 우위"입니다.
  - 배당, 세금, 환전은 반영하지 않습니다.
- **실시간 예측:**
  - 추가만 하고, 덮어쓰지 않습니다.
  - 마지막 종가가 7일보다 오래되면 예측하지 않습니다.
  - 다음 거래일 개장 이후에 기록된 예측은 집계에서 뺍니다.
  - 판정은 공식 종가로만 합니다(잠정치 제외).
- **미국 예측:** FRED 지수는 ML 학습 금지라서 SPY·QQQ(토스증권, 수정주가)로 학습·판정합니다. 지수와는 배당·보수만큼 차이가 납니다.
- **전망 변화 설명:** 검증 통과 모델에만, 같은 모델로 직전 입력과 오늘 입력을 비교하고 입력을 하나씩 되돌려 확률 변화를 나눕니다. 원인이 아니라 모델 입력의 변화입니다.

### 뉴스·브리핑
- Fed·SEC RSS와 GDELT에서 제목, URL, 시각만 저장합니다(본문 저장 없음).
- URL과 제목 유사도로 중복을 묶고, 9개 범주로 분류하고, 영문 키워드 감성(`lexicon-en-v2`)과 중요도를 매깁니다.
- 뉴스는 예측 피처로 쓰지 않습니다.
- 분류·감성 정확도는 직접 붙인 라벨로 채점합니다(`label-export` → CSV 채우기 → `label-score`). 라벨 100개 이상이고 macro-F1 0.5 이상일 때만 "평가 통과"로 표시합니다.
- 브리핑은 규칙 기반입니다. AI 요약(`--llm`)은 숫자·시장·부호·예측 어휘를 검증하고, 통과하지 못하면 규칙 기반 문장으로 대체합니다. 보관이 금지된 소스(FRED)의 수치는 SQLite와 LLM 입력에서 뺍니다.

## 5. 보안

- **키:** 환경변수로만 다룹니다. curl에는 stdin 설정으로 넘겨서 명령줄·로그·오류에 남지 않습니다. cron 키 파일은 소유자 전용(600)이어야 합니다.
- **토스증권:** 토큰에 권한 범위가 없어 주문도 가능합니다. 그래서 `mi/toss.py`는 시세 경로만 허용 목록으로 호출합니다. 주문·계좌 경로는 요청 전에 거부하고, 계좌 헤더는 보내지 않습니다. 허용 IP 등록이 필수입니다.
- **네트워크:** HTTPS만 씁니다(리다이렉트 포함). 인증 요청은 리다이렉트를 따라가지 않습니다.
- **로컬 서버(`scripts/serve.py`):** 127.0.0.1에만 열고, 대시보드 파일만 제공합니다. Host 헤더를 검사해 DNS 리바인딩을 막고(421), CSP를 붙입니다. `python3 -m http.server`는 저장소 전체를 노출하므로 쓰지 마세요.
- **파일:** JSON과 SQLite는 0600입니다. `data/`는 gitignore 대상입니다.
- **화면:** 외부 문자열은 모두 `esc()`를 거칩니다. 링크는 http(s)만 허용하고 `noopener noreferrer`를 붙입니다.

## 7. 한계

- **예측력:** 지수 방향 예측은 기준 모델을 이기기 어렵습니다. 통과한 2개도 여유가 작고, 다중 비교 때문에 낙관 편향이 남습니다.
- **비용 반영 성과:** 시가 데이터가 없어 다음 날 시초가 진입은 하루 늦은 종가로 대신했습니다. 배당, 세금, 환전은 빠져 있습니다.
- **국면·위험:** 사전에 정한 규칙이며, 미래 수익률 예측력은 검증하지 않았습니다.
- **뉴스 감성:** 영문 키워드 휴리스틱입니다. 한국어는 계산하지 않습니다(라이선스가 확인된 모델 없음).
- **데이터 지연:** KRX 공식값은 다음 날 08:00, H.10은 최대 약 1주, FRED는 다음 날에 들어옵니다.
- **기술 구조:** 정적 JSON, 빌드 없는 단일 `app.js`, SQLite 한 파일로 된 1인 로컬용입니다. 외부 배포는 하지 않았습니다(`BLUEPRINT.md` 참고).

### KRX 요청 실패 진단
- `--check-krx YYYY-MM-DD`는 하루치만 진단하고 JSON을 바꾸지 않습니다.
- HTTP 401은 키, 403은 API 활용 승인, 429는 한도 초과입니다. HTTP 000과 curl 5/6/28/56은 네트워크 문제입니다.
- "데이터 없음"은 휴장일이거나 아직 게시되지 않은 날입니다(KRX는 다음 날 08:00 게시).
- 일부 시장만 다시 받으려면: `python3 scripts/collect_data.py --markets ks`
